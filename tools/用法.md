# 工具用法

本目录 7 个脚本，按用途分三类。

---

## 统一口径（先读这一段）

```
遥测 A 单位   : 10 位计数  (1024 counts = 360°, 2.84 counts/deg)
控制内部      : 12 位计数  (4096 counts = 360°, 11.38 counts/deg)
工具内部      : A × 4 还原成 12 位

竖直向上 = A = 787 (10 位) = 3148 (12 位)
自然下垂 = A = 275 (10 位) = 1100 (12 位)
两者相差 512 (10 位) = 180.0°

状态列 T=5 表示电机使能中；只有 T=5 的帧参与统计
```

**混用 10 位和 12 位会差 4 倍。** 所有脚本都按上表换算，调用时只需给 10 位的
`--tgt 787`。

## 一、构建与烧录

### `build_pd.ps1` —— 从源码综合出 `.fs`

**前置**：装有 Gowin EDA（V1.9.11.03 或更高，教育版即可）。

```powershell
powershell -ExecutionPolicy Bypass -File .\工具\build_pd.ps1
```

默认参数即交付固件对应的构建参数（`-Stage 5 -I2cDiv 1000`），输出到 **`重建\f1_rebuild.fs`**。

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Stage` | 5 | 控制模式。5 = 倒立摆闭环 |
| `-I2cDiv` | 1000 | I2C 分频。1000 → 角度更新 4.1 ms（244 Hz） |
| `-OutName` | `f1_rebuild.fs` | 输出文件名（刻意不叫交付固件的名字） |
| `-OutDir` | 包内 `重建\` | 输出目录，**不会污染 `固件\`** |
| `-GowinBin` | 自动探测 | `gw_sh.exe` 所在目录；装在非常规位置时指定 |

**它做了什么**：在系统临时目录（纯 ASCII 路径）里新建工程，复制 `源码\`，
现场生成 `f1_attitude.gprj` 与 `build.tcl`，注入 `STAGE` / `OS_CLKDIV`，
调用 `gw_sh.exe` 综合，最后把比特流和构建记录（`.fs.txt`）放进 `重建\`。
**这样 `固件\` 里永远只有交付的那一个比特流**，不会因为跑了一次综合就出现第二个版本。

**两点说明**：

- **不会改动 `源码\` 里的任何文件** —— 参数注入只发生在临时副本上。
  因此 `源码\top.v` 的哈希始终与 `固件\...fs.txt` 里 `src_sha1` 记录一致，可自行校验。
- **工程放在临时目录**，是因为 Gowin 的 Tcl 控制台不处理非 ASCII 路径
  （包放在中文目录下会被吃成 `???`）。综合完临时目录会留在 `%TEMP%` 下，
  不占包内空间，可以随手删。

**综合时的无害提示**：`gw_sh` 会尝试往 `AppData\LocalLow\GowinSemi\IDE\cache\sh.log`
写日志，无权限时日志里会出现几行 `failed to open log file` 和 PowerShell 的
`+ FullyQualifiedErrorId : NativeCommandError` 包装。**这些与综合无关。**

脚本只把 Gowin 自己输出的 `ERROR  (PR0003) : ...` 这种格式算作真报错；
其余一律归入"已忽略 N 条与综合无关的提示"。**判成功的标准是最后打印了
`完成 -> ... CheckSum 0x????`，而不是日志里有没有 ERROR 字样。**

校验源码与固件是否同一份：

```powershell
(Get-FileHash .\源码\top.v -Algorithm SHA1).Hash
Get-Content .\固件\FPGA倒立摆_固件_0xE931.fs.txt | Select-String 'src_sha1'
```

### `program_f1.ps1` —— 烧录

```powershell
powershell -ExecutionPolicy Bypass -File .\工具\program_f1.ps1 -Mode flash -Fs .\固件\FPGA倒立摆_固件_0xE931.fs
```

**烧完必须核对打印出的 `User Code`，应为 `0x0000E931`。**
写内部 Flash，掉电保存。

## 二、数据采集

### `read_serial.ps1` —— 采遥测

```powershell
powershell -ExecutionPolicy Bypass -File .\工具\read_serial.ps1 -Seconds 60 -Live -Send "E1" -SendGapMs 90000 -Save .\run.csv
```

| 参数 | 说明 |
|---|---|
| `-Seconds` | 采集时长（秒） |
| `-Live` | 实时在屏幕打印每一帧 |
| `-Send` | 采集开始时自动发送的命令（如 `E1` 使能） |
| `-SendGapMs` | 命令重复间隔（毫秒） |
| `-Save` | 保存的 CSV 路径 |

输出 CSV 为 5 列：`时间, A, T, E, M`，100 Hz。

## 三、离线分析

### `balance_score.py` —— 平衡段评分

```powershell
python .\工具\balance_score.py .\实测数据\实测_run1.csv --tgt 787
```

| 输出项 | 含义 |
|---|---|
| `balance segments` | 摆杆角与目标差 ≤50 计数（≈17.6°）且 ≥1.0 s 的段，逐段列出 |
| `balance time` | 最长段时长 |
| `E drift rate` | 该段内臂位置漂移速率（判据 `\|rate\| < 40`） |
| `\|E\|>200 check` | 软限位是否与摆杆对抗（比较 `M` 的符号与 P+位置项应有的方向） |
| `arm limit` | 臂是否撞到 `\|E\|>450` 的硬限位 |
| `mean \|M\|` / `saturated` | 电机平均占空比 / 饱和比例 |

**`--tgt 787` 建议显式给出。** 不传时脚本会用 `M` 的过零次数自动估计平衡目标，
在这个台架上估出 662–689（偏约 100 个计数），会切不出有效平衡段、只输出 `<0.5 s`。
这份数据的正确值是 **787**。

### `swing_score.py` —— 起摆评分

```powershell
python .\工具\swing_score.py .\实测数据\实测_run1.csv --tgt 787
```

看起摆阶段：能量是否逐周期上升、摆幅是否扩大、抵达竖直附近时的残留角速度。
输出里的 `pump time` 是 `E1` → 首次进入平衡段的耗时。

### `phase_freq.py` —— 振荡频率与相位

```powershell
python .\工具\phase_freq.py .\实测数据\实测_run1.csv --tgt 787
```

用于看平衡段的抖振主频（本系统主要成分约 6.5 Hz）以及摆杆与驱动臂的相位关系。

### `dump_window.py` —— 导出指定时间窗

```powershell
python .\工具\dump_window.py .\实测数据\实测_run1.csv 30 40
```

把 30–40 s 这一段单独导出，便于画图或逐帧核对。

## 四、常见问题

| 现象 | 处理 |
|---|---|
| `build_pd.ps1` 报「未找到 Gowin EDA」 | 用 `-GowinBin "C:\Gowin\Gowin_V1.9.11.03_Education_x64\IDE\bin"` 指定 |
| 综合失败 | 脚本会把日志复制到包根目录的 `build_failed.log`，看里面的 `ERROR` 行 |
| `balance_score.py` 只输出 `<0.5 s` | 加 `--tgt 787` |
| `program_f1.ps1` 找不到设备 | 确认 USB 连接、Gowin Programmer 能识别器件 `GW1N-9C (0x1100481B)` |
| 串口无数据 | 确认 115200 8N1、TX/RX 交叉、共地 |
| 遥测里出现了 `0` 或 `4095` | 单帧坏值，工具会自动跳过，不影响统计 |
